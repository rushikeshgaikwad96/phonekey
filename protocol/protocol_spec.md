# PhoneKey Protocol Specification — Milestone 2 Edition

## 1. Cryptographic Standard
- **Algorithm**: ECDSA over NIST P-256 (secp256r1)
- **Hash Digest**: SHA-256
- **Signature Encoding**: ASN.1 DER encoded ECDSA (Standard `SHA256withECDSA`)
- **Domain Separation**: `PhoneKey-Auth-v1`
- **Challenge Size**: 32 Bytes (256-bit CSPRNG generated via Windows `BCryptGenRandom`)
- **Challenge TTL**: 30 Seconds

---

## 2. Canonical Authentication Payload ($P$) Format

The authentication signature is computed strictly over the canonical 108-byte deterministic binary representation defined below. Big-Endian (Network Byte Order) is enforced for all multi-byte integer fields.

```
Offset (Bytes)  Size (Bytes)  Field               Type        Description / Constraints
-------------------------------------------------------------------------------------------------------------
0..15           16            Domain              bytes       ASCII "PhoneKey-Auth-v1" (null-padded to 16B)
16..17          2             ProtocolVersion     uint16      0x0100 (v1.0)
18..19          2             AlgorithmID         uint16      0x0001 (ECDSA_P256_SHA256)
20..35          16            DeviceID            bytes       16-byte UUID of Android Device
36..51          16            SessionID           bytes       16-byte UUID of Unlock Session
52..67          16            IntendedPCID        bytes       16-byte UUID of Windows PC
68..99          32            Challenge           bytes       32-byte (256-bit) CSPRNG Challenge
100..107        8             ExpirationTimestamp uint64      Unix Epoch Timestamp (ms), Big-Endian
-------------------------------------------------------------------------------------------------------------
Total Payload Size: 108 Bytes
```

### Field Definitions & Encoding Rules
1. **Domain (16 Bytes)**: Fixed ASCII byte sequence `P h o n e K e y - A u t h - v 1 \0 \0`. Must match `PhoneKey-Auth-v1` exactly.
2. **ProtocolVersion (2 Bytes)**: Must equal `0x0100`. Any other version MUST be rejected as `INVALID_PROTOCOL_VERSION`.
3. **AlgorithmID (2 Bytes)**: Must equal `0x0001` (ECDSA P-256 SHA-256). Any other algorithm MUST be rejected as `INVALID_ALGORITHM`.
4. **DeviceID (16 Bytes)**: 128-bit UUID identifying the Android phone.
5. **SessionID (16 Bytes)**: 128-bit UUID created by Windows for the specific unlock attempt.
6. **IntendedPCID (16 Bytes)**: 128-bit UUID identifying the target Windows host.
7. **Challenge (32 Bytes)**: 256-bit cryptographically secure random bytes generated by Windows `BCryptGenRandom`.
8. **ExpirationTimestamp (8 Bytes)**: 64-bit unsigned integer representing Unix epoch timestamp in milliseconds when the challenge expires (Creation Time + 30,000 ms).

## 3. Error Categories

```
Error Identifier              Code (Hex)   Description
---------------------------------------------------------------------------------
SUCCESS                       0x0000       Authentication verified successfully
INVALID_REQUEST               0x0001       Malformed or incomplete binary request
INVALID_PROTOCOL_VERSION      0x0002       Unsupported protocol version number
INVALID_ALGORITHM             0x0003       Unsupported cryptographic algorithm
UNKNOWN_DEVICE                0x0004       Device ID not found in registered device table
INVALID_SIGNATURE             0x0005       ECDSA signature verification failed
CHALLENGE_NOT_FOUND           0x0006       Challenge ID not present in active challenge store
CHALLENGE_EXPIRED             0x0007       Challenge timestamp exceeded 30s TTL
CHALLENGE_ALREADY_CONSUMED    0x0008       Challenge has already been evaluated (Replay attempt)
SESSION_MISMATCH              0x0009       Session ID in response does not match issued challenge
DEVICE_MISMATCH               0x000A       Device ID does not match expected paired device
PC_MISMATCH                   0x000B       Intended PC ID does not match local Windows host ID
MALFORMED_SIGNATURE           0x000C       Signature is not valid ASN.1 DER format
CRYPTO_ERROR                  0x000D       Windows CNG or Android Keystore internal crypto failure
BIOMETRIC_REQUIRED            0x000E       Biometric authorization not performed
BIOMETRIC_FAILED              0x000F       User biometric check failed or cancelled
KEY_INVALIDATED               0x0010       Android Keystore key invalidated by biometric enrollment
```

## 4. Scope Limitations (Milestone 2 vs Future Milestones)

- **Milestone 2 (Current Scope)**:
  - Canonical binary payload definition & serialization tests.
  - Android Keystore ECDSA P-256 key generation (`BIOMETRIC_STRONG`, `setInvalidatedByBiometricEnrollment(true)`).
  - BiometricPrompt signature gating (`CryptoObject`).
  - Windows CNG (`BCrypt`) ECDSA signature verification & public key import.
  - Single-use challenge store & 30s TTL expiration enforcement.
  - Deterministic cross-platform test vector suite.
  - Unit, integration, and parser fuzz testing.

- **Future Milestones (Out of Scope for Milestone 2)**:
  - *Milestone 3*: QR code scanning, Ephemeral ECDH, HKDF, SAS 6-digit confirmation PIN.
  - *Milestone 4*: Wi-Fi / Bluetooth LE transport channels, Noise Protocol, TLS sockets.
  - *Milestone 5*: End-to-End Android App & Windows Service integration over network.
  - *Milestone 6*: Windows Credential Provider COM DLL integration (`logonui.exe`, Named Pipes IPC, local logon credentials).
